# Database Migrations with Alembic

This directory contains Alembic migrations for managing database schema changes.

## Quick Reference

### Check current migration status
```bash
uv run alembic current
```

### Create a new migration (autogenerate from model changes)
```bash
uv run alembic revision --autogenerate -m "Description of changes"
```

### Create a new empty migration (manual)
```bash
uv run alembic revision -m "Description of changes"
```

### Apply migrations
```bash
# Upgrade to the latest version
uv run alembic upgrade head

# Upgrade by one revision
uv run alembic upgrade +1

# Upgrade to a specific revision
uv run alembic upgrade <revision_id>
```

### Rollback migrations
```bash
# Downgrade by one revision
uv run alembic downgrade -1

# Downgrade to a specific revision
uv run alembic downgrade <revision_id>

# Rollback all migrations
uv run alembic downgrade base
```

### View migration history
```bash
# Show current revision
uv run alembic current

# Show migration history
uv run alembic history

# Show verbose history with details
uv run alembic history --verbose
```

## Workflow

### 1. Modify your SQLAlchemy models
Edit files in `api/*/models.py` to add/modify tables and columns.

### 2. Generate a migration
```bash
uv run alembic revision --autogenerate -m "Add user authentication"
```

### 3. Review the generated migration
Check the file in `api/alembic/versions/` to ensure it captured your changes correctly. Alembic's autogenerate is smart but not perfect - always review before applying.

### 4. Apply the migration
```bash
uv run alembic upgrade head
```

## Important Notes

- Always review autogenerated migrations before applying them
- Test migrations on a development database first
- Alembic reads `DATABASE_URL` from the `.env` file
- All models must be imported in `api/alembic/env.py` for autogenerate to detect them
- For production deployments, run migrations as part of your deployment process

## Common Issues

### Alembic doesn't detect my model changes
- Ensure your model is imported in `api/alembic/env.py`
- Check that your model inherits from `Base` (from `api.database`)
- Verify the model is properly defined with SQLAlchemy 2.0 syntax

### Migration conflicts
If multiple developers create migrations simultaneously:
```bash
# Merge the migration branches
uv run alembic merge -m "Merge migrations" <rev1> <rev2>
```

## Migration Best Practices

1. **One logical change per migration** - Keep migrations focused
2. **Always include downgrade logic** - Make migrations reversible when possible
3. **Test both upgrade and downgrade** - Ensure rollbacks work
4. **Add data migrations carefully** - Be cautious with large datasets
5. **Document complex migrations** - Add comments explaining why, not just what
